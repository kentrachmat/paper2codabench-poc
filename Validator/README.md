# Competition Bundle Validator

A lightweight Python validator for Codabench competition bundles.

This script verifies the structure of a competition bundle folder before upload. It checks required fields, validates file references, enforces structural constraints, and performs consistency checks across tasks, phases, pages, and leaderboards.

------------------------------------------------------------
What It Validates
------------------------------------------------------------

The validator performs the following checks:

- Presence of competition.yaml
- Required top-level fields:
  - title
  - image
  - tasks
  - phases
  - leaderboards
  - pages
  - terms
  - docker_image

Image
- Must be JPG, JPEG, or PNG
- File must exist in the bundle

Pages
- At least one page required
- Each page must have:
  - title
  - file
- Page files must exist
- Page files must not be empty

Tasks
- Unique task indexes
- scoring_program is required
- ingestion_program, input_data, reference_data are optional
- If optional files are provided, they must exist

Terms
- Terms file must exist
- Terms file must not be empty

Phases
- At least one phase required
- Sequential date validation
- Referenced files (public_data, starting_kit) must exist if provided

Leaderboards
- At least one leaderboard required
- Unique leaderboard indexes
- Required fields:
  - index
  - title
  - key
  - submission_rule
- At least one column required per leaderboard
- Columns must contain:
  - index
  - title
  - key
- Column indexes must be unique within each leaderboard

Usage
------------------------------------------------------------

Run from the repository root:

```
python3 competition_bundle_validator.py <bundle_path>
```

Example:

```
python3 competition_bundle_validator.py ./my_competition_bundle
```

If the bundle is valid:
```

[+] Bundle is valid!
```

If validation fails:

```

```

------------------------------------------------------------
Croissant Task Validator
------------------------------------------------------------

A validator for Croissant Task (cr:TaskProblem) JSON-LD files generated by Pipeline A.

This validator checks LLM-generated Croissant Tasks against:
1. **Formal Croissant Task Vocabulary spec** (JSON-LD structure, required fields)
2. **Component completeness** (cr:input, cr:output, cr:evaluation, cr:implementation, cr:execution)
3. **Type correctness** (dataType values, numeric types, boolean types)
4. **FILL IN THE BLANK detection** (identifies placeholder strings and cross-references with fill_in_the_blank array)
5. **Pipeline compatibility** (descriptions needed for bundle generation)

------------------------------------------------------------
What It Validates
------------------------------------------------------------

**Level 1 - JSON-LD / Structural (errors):**
- Valid JSON, root is a dict
- `@context` present with required namespaces (`cr`, `sc`/`schema`)
- `@type` is `cr:TaskProblem`
- `conformsTo` present and references Croissant spec
- `@id`, `name`, `description` present and non-empty

**Level 2 - Component Completeness (errors/warnings):**
- `cr:input`: must exist, be a list with at least one entry; each entry should have `name` and `description`
- `cr:output`: must exist, should have `cr:schema` with `@type: cr:RecordSet` and at least one field
- `cr:evaluation`: must exist, should have `primaryMetric` (non-empty string) and `metrics` (non-empty list)
- `cr:implementation`: recommended, should have `entryPoint`
- `cr:execution`: recommended, `runtimeLimitSec` and `memoryLimitMb` should be numeric

**Level 3 - Type and Value Correctness (errors/warnings):**
- `dataType` values must be from valid set: `sc:Text`, `sc:Integer`, `sc:Float`, `sc:Boolean`, `sc:URL`, `sc:ImageObject`
- `runtimeLimitSec` and `memoryLimitMb` must be numeric, not strings
- `higherIsBetter` must be boolean
- `primaryMetric` should appear in the `metrics` list

**Level 4 - FILL IN THE BLANK Detection (info/warnings):**
- Scans all string values recursively for `[FILL IN THE BLANK: ...]` patterns
- Counts and reports each occurrence with JSON path
- Cross-references with `fill_in_the_blank` array (warns if mismatched)

**Level 5 - Pipeline Compatibility (warnings):**
- Output schema fields should have descriptions (needed for toy data generation)
- Input descriptions should be concrete (non-empty, sufficient length)
- Evaluation notes present if metrics are non-standard

Usage
------------------------------------------------------------

**Single file:**
```bash
python Validator/croissant_task_validator.py croissant_tasks/paper1.croissant_task.json
```

**Directory (all *.croissant_task.json files):**
```bash
python Validator/croissant_task_validator.py croissant_tasks/
```

**JSON output (for programmatic use):**
```bash
python Validator/croissant_task_validator.py croissant_tasks/ --json
```

**As a Python library:**
```python
from Validator.croissant_task_validator import validate_file, CroissantTaskValidator
from pathlib import Path

# Validate a file
result = validate_file(Path("croissant_tasks/paper1.croissant_task.json"))
print(f"Valid: {result.valid}")
print(f"Errors: {result.errors}")
print(f"Warnings: {result.warnings}")
print(f"FITB count: {result.fitb_count}")

# Validate in-memory data
import json
with open("task.json") as f:
    data = json.load(f)
validator = CroissantTaskValidator(data)
result = validator.validate()
```
